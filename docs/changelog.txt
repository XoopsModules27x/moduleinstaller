ModuleInstaller CHANGELOG
=========================

--------------------------------------------------------------------------------
1.7.0 Alpha 1  [2026-07-30]
Dev: XOOPS 2.7.0+, PHP 8.2+, mtools 1.2.0+
--------------------------------------------------------------------------------

Highlights
- Rebuilt install-action reporting as structured data that can be rendered safely
  to HTML or consumed as plain text, CLI output, logs, or JSON.
- Hardened admin reports against unsafe module-supplied markup, paths, malformed
  manifests, invalid UTF-8, and incomplete or malformed language packs.
- Improved translated and RTL admin output, accessibility, and responsive styling
  without breaking existing ModuleActionService callers.

Security / correctness
- The install-log renderer now parses untrusted core HTML into typed events,
  escapes every value exactly once, emits only fixed module-owned markup, and
  discards executable or raw-text element bodies.
- Module logo URLs now use one validated, platform-aware path resolver; unsafe,
  remote, missing, and traversal paths are rejected.
- Manifest loading failures no longer replace a completed operation report with a
  blank page.
- Fixed invalid UTF-8 caused by byte-based NBSP trimming and duplicate failure
  transcripts in structured output.

Structured reports and compatibility
- Added the class/Report/ package with typed log fragments, events, severities,
  outcomes, operation results, a legacy adapter, and the HTML renderer.
- ModuleActionResult now exposes events(), messageText(), and
  toOperationResult(); ModuleActionService adds operationResult() and
  operationResults().
- ModuleActionResult is deprecated in favor of Report\ModuleOperationResult, while
  existing runOne()/runMany() signatures remain supported through XOOPS 2.8.
- Structured results expose a combined severity for consumers while preserving
  the distinction between the operation outcome and errors reported by core.

Internationalisation and admin UI
- Added 30 translatable admin-report strings and Lang helpers with safe English
  fallbacks for missing, blank, non-scalar, or malformed translations.
- Added bidirectional isolation for counters, versions, statuses, folders, and
  plan summaries in RTL admin interfaces.
- Improved long-report scrolling and screen-reader ordering; converted module CSS
  to logical properties and removed module-owned inline style attributes.

Tests
- Expanded the suite to 109 tests / 264 assertions covering hostile log input,
  structured-result contracts, language fallbacks, logo-path rejection and UTF-8
  boundary handling.
- The module-logo POSITIVE path and the image-extension allowlist are not unit
  covered: both need a real file under XOOPS_ROOT_PATH/modules/<dirname>/, so they
  belong to the integration suite. Only the rejection contract is asserted here.

--------------------------------------------------------------------------------
1.6.0 Stable  [2026-07-23]
Dev: XOOPS 2.7.0+, PHP 8.2+, mtools 1.2.0+
--------------------------------------------------------------------------------

Highlights
- Module Sets for focused testing (named YAML collections of modules).
- Shared safe bulk-action service for install / uninstall / update / activate /
  deactivate (skips missing modules; does not fatal mid-batch).
- mtools 1.2.0 consumer bootstrap and lifecycle hooks.
- Platform requirements raised to PHP 8.2 and XOOPS 2.7.0.
- Phase 3: pure CP chrome for bulk tabs; wizard baggage removed.
- Sample module sets (PM/Profile/Protector); scoped admin.css for UX only.

Features — Module Sets
- New admin page: Module Sets (admin/sets.php), menu item _MI_MODULEINSTALLER_MENU_06.
- Create, edit, duplicate, and delete named sets.
- Snapshot currently active modules into a new set.
- Apply actions per set:
  - Activate set members
  - Deactivate set members
  - Install set members
  - Uninstall set members
  - Focus: activate set members and deactivate all other non-protected modules
    (system and moduleinstaller are never touched). Auto-snapshot before Focus.
- Dry-run plan / preview before apply; confirmation for destructive actions.
- Missing-on-disk members are listed as notices and skipped (never fatal).
- Storage: YAML under XOOPS_VAR_PATH/configs/moduleinstaller/sets/ (web-denied).
- Classes under class/Set/:
  ModuleSet, ModuleSetRepository, ModuleSetResolver, ModuleSetApplier.

Features — bulk actions refactor
- class/ModuleActionService.php: single service for bulk install/uninstall/
  activate/deactivate/update.
- class/ModuleActionResult.php: structured per-module success/skip/fail results.
- class/ModuleCatalog.php: installed / available / active module inventory.
- class/AdminBulkPage.php: shared admin UI for bulk tabs.
- admin/install.php, uninstall.php, activate.php, deactivate.php, update.php
  rewritten to use the service (much smaller admin scripts).
- “Apply set” helpers on bulk pages to pre-check set members.

mtools / install lifecycle
- bootstrap.php: registers module namespace then loads mtools bootstrap.
- include/mtools_dependency.php: ConsumerRuntime dependency check (API 1.0.0 +
  module 1.2.0); mtools must be installed (need not be active).
- xoops_version.php: min_modules mtools >= 1.2.0; min_php 8.2; min_xoops 2.7.0.
- onInstall / onUpdate / onUninstall registered; mtools Module\Installer pattern.
- Utility extends mtools SysUtility where applicable.

Security / robustness
- Xmf\Request for admin input (no raw $_REQUEST for control flow).
- CSRF checks on set mutations.
- Null-safety when dirname is missing on activate/deactivate paths.
- Protected modules (system, moduleinstaller) excluded from destructive bulk /
  Focus operations.
- Batch actions continue after individual failures and report notices.

Quality / tooling (new vs 1.5.1)
- PHPUnit 11 suite (phpunit.xml.dist, tests/bootstrap.php, tests/Unit/…).
  Coverage for ModuleSet*, ModuleActionResult, InstallWizard, Helper, Common
  helpers, preloads.
- phpstan.neon and phpstan analysis notes.
- Expanded language strings (admin sets UI, apply-set hints).

UX polish (introduced in 1.6.0)
- Apply Set form: clearer vertical spacing between intro, Action, Preview plan,
  Set member status, confirm checkbox, and Run/Cancel.
- Module Set edit: selected members highlighted with light green (#E6EFC2),
  consistent with bulk Yes rows.
- Bulk tabs and set edit: click module logo or name/description to toggle
  selection (same as radio / checkbox).
- docs/TUTORIAL.md end-user walkthrough.

Phase 1–2 UX (introduced in 1.6.0, 2026-07-23)
- Bulk + set-edit filter box; keyboard / and A; sticky “N selected” bar;
  empty Yes selection blocked on submit.
- Status badges; Apply plan summary counts; Focus/Uninstall confirm copy split;
  restore last Focus snapshot from result + dashboard.
- Update tab pre-selects version mismatches; needs_only filter link.
- Home dashboard (sets, updates, counts, last snapshot).
- Module set YAML export/import.
- Tooltips on Apply; CSS --installer-selected; responsive hide descriptions.
- ModuleCatalog::candidatesFor / needsUpdate helpers.
- docs/TODO.md updated; docs/MTOOLS-INVESTIGATION.md (Phase 3 prerequisite).

Phase 3 structure & polish (introduced in 1.6.0, 2026-07-23)
- Bulk tabs: AdminBulkPage::serve() only (no install_tpl / InstallWizard dual chrome).
- Thin admin wrappers; CSRF on bulk POST; renderReport in presentation layer.
- Removed extras/, wizard files (InstallWizard, common.inc, install_tpl, page.php,
  include/config.php, language/english/install.php, prototype.js).
- admin.css only for .installer-* UX; CP chrome from ModuleAdmin + admin theme.
- Sample data: TestdataButtons + pm-profile-protector sample set.
- Language common.php: fixed _CO_MODULEINSTALLER_* constants.
- UX: Apply set blue panel, set list/edit panels, logos, even/odd rows, sticky
  Select All, title count without italics, first-row Yes/No layout.
- Removed local class/Common/* forks and tests; depend on mtools Common only.
- Adopted module-devops baseline (composer.json QA scripts, phpstan.neon.dist,
  php-cs-fixer, rector, .github workflows, stubs, sonar opt-in).

Docs
- README.md, docs/readme.txt, docs/TUTORIAL.md, CHANGELOG.md for 1.6.0 release.
